Export to Figma sends your Figr prototype into Figma as editable layers. Frames arrive with auto layout and your variables mapped, and elements that match your design system come in as instances of your Figma library components. Designers pick up the work in Figma without rebuilding it.

## Before you start

You need the **Figr AI Figma Sync** plugin installed and connected. If you set it up for [Figma input](/input-research/figma-input), you're ready.

## Export a prototype

<Steps>
  <Step title="Select the prototype">
    Click the prototype on the canvas. Its toolbar shows **Interact**, **Edit**, **Full screen**, **Context**, **Export** and **More**.
  </Step>
  <Step title="Choose what to export">
    Open **Export**. Choose **Export screens** to pick specific screens, or **Export all screens** to send the whole flow in one run.
  </Step>
  <Step title="Run the plugin in your target Figma file">
    Open the plugin in the Figma file where the design should land. Keep Figma in the foreground while the export runs.
  </Step>
  <Step title="Follow the progress">
    Figr shows progress for each screen. If one screen fails, the others still complete and the error is shown against that screen.
  </Step>
  <Step title="Pick it up in Figma">
    When Figr confirms the design was sent, your frames are on the Figma canvas, ready to refine.
  </Step>
</Steps>

## What comes across

| What | How it arrives in Figma |
| --- | --- |
| Layout | Frames with auto layout, so they resize like a real Figma design |
| Design values | Mapped to your Figma variables, not flattened into one-off styles |
| Design system components | Instances of your Figma library components, where Figr can match them |
| Anything Figr can't match | A regular frame, with a note explaining why it wasn't linked |

Change a variable in Figma and the exported design updates with it.

<Note>
  Component instances need a design system set up from Figma. See [Design System](/product-intelligence/design-system).
</Note>

## Good to know

- **Each export is a copy.** Edits you make in Figr later don't update the Figma copy. Export again to send the new version.
- **Large exports retry on their own.** Image-heavy screens and slow connections are handled with retries instead of failing the whole run.

## Other ways to hand off

The **Export** menu has more options for when the work goes somewhere other than Figma:

| Option | Best for |
| --- | --- |
| Export screens / Export all screens | Handing off to a designer in Figma |
| Copy code | Pasting the component code into your project |
| Download PNG, PDF or Markdown | Dropping a visual or doc into a deck, ticket or message |
| Copy as text | Pasting the content of a doc or screen |
| Add to Context Pod | Reusing this design as context in future work |
| Open in coding agent | Building it in Claude Code, Cursor, VS Code or Codex through [Figr MCP](/export/mcp) |

## Troubleshooting

| Issue | Fix |
| --- | --- |
| Figr can't find the plugin | Run Figr AI Figma Sync in your target Figma file and check it shows **Connected**, then retry |
| The plugin says Figma is in the background | Bring the Figma window to the front. The export continues |
| One screen failed | Check the error shown for that screen, then export just that screen again |
| An element came across as a frame, not a component | Read the note on the frame. Usually the component isn't in the design system Figr used |
