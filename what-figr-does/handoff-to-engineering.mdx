A screenshot or an HTML export isn't a handoff. Engineers still have to work out the structure, guess the spacing and swap in their own components. Teams end up reworking about half of what they receive by hand before it can ship.

Figr hands the real design to engineering, inside the tools they already use.

<Frame>
  <img

</Frame>

<Tip>
  **The short version:** Engineers connect their coding agent (Claude Code, Cursor, VS Code, Codex and others) to Figr once. From then on, the agent reads the actual design, its structure, values and the reasoning behind it, and builds from that instead of a picture.
</Tip>

**Example on this page:** FreshFold, a laundry pickup and delivery app. Customers book a pickup in the app, a rider collects the bag, and clean clothes come back within 24 hours.

## How it works

<Steps>
  <Step title="Pick the design">
    Select a prototype on the canvas and choose **Export**, then **Open in coding agent**. In the FreshFold example: the approved pickup confirmation screen.

    <Frame>
      <img
        alt="Open in coding agent option in the Export menu of a selected Figr prototype"
        title="Open a Figr design in a coding agent"
        src="/images/Screenshot-2026-10-21-at-2.20.45-AM.png"
      />
    </Frame>
  </Step>
  <Step title="Connect the coding agent">
    Follow the steps in the **Connect with coding agent** window for your agent, or add the Figr MCP server to your editor once so it can reach every project you have access to.

    <Frame>
      <img
        alt="Connect with coding agent window with setup for Claude Code, Cursor, VS Code and Codex"
        title="Connect a coding agent to Figr MCP"
        src="/images/Screenshot-2026-10-21-at-2.21.03-AM.png"
      />
    </Frame>
  </Step>
  <Step title="The agent reads the real design">
    The agent sees the layout, values and structure, plus the decisions from your conversations with Figr.
  </Step>
  <Step title="The agent builds in your code">
    The agent builds the screen in your codebase with your components, starting from the design instead of a guess.
  </Step>
</Steps>

## What changes for your team

- **Engineers** build from the design, not a screenshot.
- **Designers** stop answering "what's the spacing here?"
- **Rework** after handoff drops, because nothing gets lost in translation.
