A screenshot or an HTML export isn't a handoff. Engineers still have to work out the structure, guess the spacing and swap in their own components. One team estimated that half of what they received needed manual rework before it could ship.

Figr hands the real design to engineering, inside the tools they already use.

<Note>
  **The short version:** Engineers connect their coding agent (Cursor, Claude Code, VS Code and others) to Figr once. From then on, the agent reads the actual design: its structure, values and the reasoning behind it, and builds from that instead of a picture.
</Note>

## How it works

<Steps>
  <Step title="Pick the design">
    Select a prototype on the canvas and choose **Export**, then **Use MCP server**. In the Ledgerly example: the approved approvals screen.

    <Info>
      **Asset needed · 7.1**: Screenshot of the Use MCP server dialog for the Ledgerly approvals screen, with the Project link and Board node link buttons visible.
    </Info>
  </Step>
  <Step title="Connect the coding agent">
    Paste the link into the agent's MCP setup, or register the Figr MCP server once for the whole workspace.
  </Step>
  <Step title="The agent reads the real design">
    The agent sees the layout, values and structure, plus the decisions from your conversations with Figr.
  </Step>
  <Step title="The agent builds in your code">
    The agent builds the screen in your codebase, starting from the design instead of a guess.

    <Info>
      **Asset needed · 7.2**: Screenshot of the coding agent's chat calling Figr MCP and returning the Ledgerly approvals screen's structure.
    </Info>
  </Step>
</Steps>

## See it work

The moment that matters: an engineer asks their own agent for the screen, and it pulls the design straight from Figr.

<Info>
  **Asset needed · 7.3 (proof moment)**: 20–30s screen recording in Cursor or Claude Code. The engineer types the prompt, the agent calls Figr MCP, and the generated Ledgerly screen code uses the team's components.
</Info>

## What changes for your team

- **Engineers** build from the design, not a screenshot.
- **Designers** stop answering "what's the spacing here?"
- **Rework** after handoff drops, because nothing gets lost in translation.
