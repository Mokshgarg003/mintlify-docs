## Getting started

<AccordionGroup>
  <Accordion title="What makes Figr different from other AI design tools?">
    Figr is built for teams designing on top of a product that already exists. It learns your product from Context Pods and your Design System, then designs inside them: your components, your tokens, your flows and your states. The output exports to Figma with auto layout and your library components, or goes to code through Figr MCP, so designers refine it instead of rebuilding it.
  </Accordion>
  <Accordion title="How long does it take to set up Figr for my product?">
    A first useful setup takes minutes: one recording, a few screenshots or a Figma file. A full setup for a complex product, with a design system and several Context Pods, takes longer and pays off on every project after.

    Enterprise teams get onboarding with the Figr team. [Talk to us](https://figr.design/contact) to set it up.
  </Accordion>
  <Accordion title="Do I need design experience to use Figr?">
    No. Figr asks questions, explores directions and explains its reasoning. PMs use it for flows, edge cases and first passes. Designers use it to explore faster and hand off cleaner work.
  </Accordion>
  <Accordion title="Does Figr work with my existing tools?">
    Yes. Figr takes Figma, Storybook, npm packages and GitHub as design system sources, and connects to tools like Notion, Confluence, Linear, Asana, Slack, Mixpanel and Amplitude. Output goes to Figma, to code, or to coding agents like Claude Code, Cursor, VS Code and Codex.
  </Accordion>
</AccordionGroup>

## Features

<AccordionGroup>
  <Accordion title="How does Figr remember my product?">
    Context Pods hold what Figr knows about your product: recordings, files, notes, links and instructions. Figr also keeps memory of product decisions, constraints and preferences across your work, pulls relevant decisions from earlier chats in the same pod, and shows which memories or sources it used. See [Context Pods](/product-intelligence/context-pods).
  </Accordion>
  <Accordion title="What can I upload?">
    Images (PNG, JPG, WebP, GIF, SVG), videos (MP4, MOV, MKV, WebM), PDFs, Markdown, text, CSV, JSON, CSS, HTML and Mermaid files. Word, Excel and PowerPoint files aren't supported, so export them to PDF first. You can also record a walkthrough inside Figr or capture pages with the Figr Capture Chrome extension.
  </Accordion>
  <Accordion title="Can my team work together in Figr?">
    Yes. Teammates see each other's live cursors on the canvas, comment on designs, and run separate chats in the same project. Share a project with view or edit access, and share Context Pods and design systems across the workspace.
  </Accordion>
  <Accordion title="Does Figr work for mobile app design?">
    Yes. Figr designs for web and mobile, and builds prototypes in React or Angular. 
  </Accordion>
  <Accordion title="How do I hand off to engineering?">
    Export screens to Figma with auto layout and your components, download the code, or click **Open in coding agent** to connect Claude Code, Cursor, VS Code or Codex through [Figr MCP](/export/mcp).
  </Accordion>
</AccordionGroup>

## Security and admin

<AccordionGroup>
  <Accordion title="How secure is my data in Figr?">
    Figr is SOC 2 Type II compliant, and your data is encrypted in transit and at rest. Enterprise plans include SSO and EU data residency. See [Data protection](/legal/data-protection) for details.
  </Accordion>
  <Accordion title="Does Figr support SSO?">
    Yes, on Team and Enterprise plans. Figr supports SAML and OIDC, set up by a workspace owner or admin.
  </Accordion>
  <Accordion title="What can connectors access?">
    A connector can read only what the account you connect it with can read. For GitHub, you choose exactly which repositories Figr can access. You can turn any connector off at any time.
  </Accordion>
</AccordionGroup>
