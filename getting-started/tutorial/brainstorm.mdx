## Pick a mode

The mode picker below the chat box sets how Figr responds.

| Mode | What Figr does | Use it when |
| --- | --- | --- |
| Auto | Decides when to think and when to design, and moves from one to the other on its own | Most of the time |
| Brainstorm | Explores options, trade-offs, flows and edge cases without building screens | The problem isn't clear yet |
| Design | Goes straight to building screens and prototypes | You know what you want |

## When to brainstorm

Use Brainstorm when you're still deciding:

- What the user journey should be
- Which UX approach makes sense
- Which edge cases matter
- What a screen should include
- What trade-offs exist and which assumptions need checking

Good Brainstorm prompts:

- "What are the edge cases for a guest checkout flow?"
- "Compare three onboarding approaches for a B2B analytics tool."
- "Given this PRD, what requirements are unclear from a UX perspective?"
- "Review this feature idea and suggest the safest MVP flow."

Brainstorm output can include structured options, trade-off breakdowns, flow diagrams, wireframes, PRD-style docs, UX risks and edge-case lists. Attach a [Context Pod](/product-intelligence/context-pods) so the ideas come from your real product, not generic patterns.

Brainstorm before you design when the problem is unclear. Then switch to Design, or let Auto move on when the direction is set.
