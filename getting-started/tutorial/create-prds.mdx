A PM handoff isn't only a doc, and it isn't only a screen. From one rough problem, Figr builds the chain of artifacts a real handoff needs, and keeps them connected on one canvas.

From a single problem, Figr can produce:

- A PRD and requirements
- User stories and acceptance criteria
- Edge-case maps and key states
- Test cases
- A user flow
- A high-fidelity prototype

## Write a PRD

<Steps>
  <Step title="Attach your context">
    Attach your [Context Pod](/product-intelligence/context-pods), plus any research, feedback or a page from a connected tool like Notion or Linear.
  </Step>
  <Step title="Describe the problem">
    It doesn't need to be polished. Say what you want to improve, who it's for, which constraints matter, and what's out of scope.

    ```text
    Turn this rough product problem into a structured PRD. Use the attached product context, existing screens, analytics notes and previous decisions, then flag missing requirements and edge cases.
    ```
  </Step>
  <Step title="Review the draft on the canvas">
    The PRD lands on your canvas as a doc. Edit it in place, or open it in full screen for more room.
  </Step>
  <Step title="Build the rest of the chain">
    Ask for user stories, acceptance criteria, test cases, the user flow, key states and the prototype.
  </Step>
</Steps>

## Keep the chain live

The PRD isn't meant to sit alone. If the flow reveals a missing state, update the PRD. If the prototype exposes a confusing interaction, update the flow.

## Share it

- **Download** the PRD as PDF or Markdown, or **Copy as text**, from the Export menu.
- **Share the project** so teammates see the PRD next to the flow and prototype. See [Publish and share](/export/publish).
- **Add to Context Pod** so future work starts from the decisions in it.

<Tip>
  Tell Figr what's out of scope. A clear "not doing" list keeps the draft focused.
</Tip>
