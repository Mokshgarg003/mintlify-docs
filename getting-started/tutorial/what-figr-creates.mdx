Because Figr understands your product, it creates the artifacts product teams need before, during and after design, and keeps them connected on one canvas.

<img
  alt="PRD, user flow and prototype connected on the canvas"
  style={{ width:"93%" }}
  src="/images/What-Figr-Creates.avif"
/>

| Artifact | What it is | Learn more |
| --- | --- | --- |
| Prototypes | Clickable, high-fidelity screens in your design system, built in React or Angular | [Prototypes](/getting-started/tutorial/prototypes) |
| Screens | Every route and state of a prototype on one board: loading, empty, error and success | [Map edge cases](/getting-started/tutorial/map-edge-cases) |
| Wireframes | Low-fidelity layouts to compare structure before visual design | [Sketch wireframes](/create/wireframes) |
| User flows | Editable diagrams of steps, decisions and branches, exportable as PNG or SVG | [Map a user flow](/create/map-user-flow) |
| UX reviews | Issues pinned to your screens, with reasoning and fixes | [UX review](/getting-started/tutorial/review) |
| PRDs and docs | PRDs, specs, user stories and acceptance criteria you can edit on the canvas | [Write PRDs and docs](/getting-started/tutorial/create-prds) |
| Test cases | Steps, expected results and edge cases, ready for QA | [Generate test cases](/create/test-cases) |
| Edge-case maps | The states and failure paths a feature needs to handle | [Map edge cases](/getting-started/tutorial/map-edge-cases) |
