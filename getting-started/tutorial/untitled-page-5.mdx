Most AI tools regenerate the whole screen for one small change, so fixing a button shifts the layout and improving the copy breaks the spacing. In Figr, you change one part and the rest stays exactly as it was.

Regenerate when the direction is wrong. Edit when the direction is right but the details need work.

## Edit a prototype

<Steps>
  <Step title="Enter Edit mode">
    Select the prototype and click **Edit** in its toolbar, or open it in **Full screen** and switch to the **Edit** tab.
  </Step>
  <Step title="Select an element">
    Click the text, button, card or section you want to change.
  </Step>
  <Step title="Change it directly or with a prompt">
    Change its text, colour, font, size, spacing, borders or radius in the panel, or type a prompt for just that element. See [Direct editing](/export/direct-editing) for what you can change.
  </Step>
  <Step title="Preview, then apply">
    Changes preview live. Make several edits, then apply them together. If you try to leave Edit mode with unapplied changes, Figr warns you first.
  </Step>
</Steps>

<Note>
  Editing a shared component applies the change everywhere that component appears in the prototype.
</Note>

## Edit a wireframe

Wireframes support the same idea: change one part of a wireframe without generating the whole thing again.

## Good prompts for a selected element

- "Make this warning clearer."
- "Use the side panel pattern from this reference."
- "Add the empty state for users with no integrations."
- "Make only this table more compact."
- "Change the hierarchy in this card without changing the rest of the page."

## When to prompt instead

Use a chat prompt when the change affects several screens, needs new content, or needs Figr to reason through the UX.
